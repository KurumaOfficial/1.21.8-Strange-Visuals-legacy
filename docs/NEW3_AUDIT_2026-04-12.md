# NEW3 Audit

Date: 2026-04-12

## Scope

- Audited the active project in `Strange/New3`.
- Covered build configuration, runtime storage, project hygiene, `src/client/java`, `src/client/resources`, and documentation.
- Treated `build/`, `.gradle/`, `run/`, and `src1/` as generated, runtime, or archival content rather than active production source.

## What Was Verified

- Baseline Gradle build and compiler warnings.
- Render and particle hot paths.
- Persistence layer for configs, alt accounts, friends, GUI settings, and item shader profiles.
- Repo hygiene and active source-set layout.

## Improvements Applied

### 1. Storage Reliability

- Added `AtomicFileIO` as a shared helper for UTF-8 atomic writes and safe move fallback behavior.
- Refactored the following storage-heavy classes to use the shared implementation:
  - `ConfigManager`
  - `FriendManager`
  - `AltAccountStore`
  - `GuiLocalization`
  - `ItemShaderProfiles`

Result:

- less duplicated filesystem logic;
- consistent temp-file behavior;
- safer cleanup on write failures;
- easier future maintenance.

### 2. Compiler Warning Cleanup

- Replaced the generic `Interpolator.lerp(...)` implementation with strongly typed overloads for `int`, `float`, and `double`.

Result:

- removed unchecked generic casting;
- made interpolation behavior explicit;
- reduced warning noise and type ambiguity.

### 3. Particle Hot-Path Cleanup

- Refactored `ParticleUtil.Particle` to store position and velocity as primitive fields instead of recreating `Vec3d` instances during updates.
- Updated particle rendering to read primitive coordinates directly in the hot path.

Result:

- lower GC pressure during particle-heavy scenes;
- cleaner real-time rendering behavior;
- better fit for long-running visual effects.

### 4. Random/Utility Cleanup

- Normalized the random helper layer in `MathHelper` to use `ThreadLocalRandom` instead of repeated `Math.random()`, ad-hoc `new Random()`, and per-call `SecureRandom`.
- Replaced remaining direct `Math.random()` hot-path usage in `Svetych` and `Trails`.

Result:

- less allocation and entropy overhead in visual systems;
- cleaner and more predictable range handling;
- easier future maintenance of utility math helpers.

### 5. Font Measurement Cleanup

- Added reusable thread-local `GlyphBuffer` measurement buffers to:
  - `FontRenderer`
  - `FontUtils`

Result:

- lower temporary allocation pressure during width measurement;
- cheaper repeated HUD/text layout work;
- better fit for per-frame UI rendering.

### 6. Project Hygiene

- Expanded `.gitignore` for the real local workflow (`.idea`, `run`, crash dumps, etc.).
- Updated `README.md` to clarify:
  - active source set is `src/client`;
  - `src1` is legacy/archive code;
  - runtime data lives in `run/`;
  - jars are produced under `build/libs/`.

### 7. Dependency Hygiene

- Added compile-only `j2objc-annotations` in `build.gradle` to satisfy missing annotation types referenced by dependencies during compilation.
- Removed unused `org.json` from `build.gradle`, since the project does not reference it anymore and it only produced Loom noise during packaging.

### 8. GPS Route Pipeline Cleanup

- Refactored `GPS` route rebuilding to use reusable route buffers instead of creating fresh `ArrayList` instances on every rebuild and post-process pass.
- Centralized route invalidation logic so target changes, world transitions, and disabled line rendering all reset the same state consistently.
- Reworked surface probing to reuse a shared `BlockPos.Mutable` during height/collision scans instead of allocating a new block position for every sampled Y level.

Result:

- lower allocation pressure during route recalculation;
- cleaner control flow in a previously fragile hotspot;
- easier future extraction of route-building logic into smaller services.

### 9. Audit Tracking

- Added `docs/NEW3_REVIEW_LOG_2026-04-12.md` as a live checklist of reviewed files, completed refactors, and next hotspot targets.

Result:

- reduces the chance of re-auditing the same areas blindly;
- keeps the next passes targeted and sequential;
- makes the remaining cleanup queue explicit.

### 10. Menu Background Pipeline Cleanup

- Extracted the duplicated initialize/refresh setup path in `MenuBackgroundManager` into a shared background-source preparation step.
- Removed per-pixel temporary `float[]` allocations from cubemap face sampling by switching `CubemapFace` direction resolution to primitive component methods.
- Tightened minor collection sizing and locale-sensitive filename normalization in the menu-background loader path.

Result:

- cheaper background import/generation for large panoramas;
- cleaner lifecycle flow around menu background initialization;
- less incidental garbage and less brittle filename handling.

### 11. TargetESP Render Hot-Path Cleanup

- Replaced per-frame `BufferAllocator` and `VertexConsumerProvider.Immediate` creation in `TargetESP` with reusable render buffers owned by the module instance.
- Added shared runtime reset helpers for target changes and module disable flow instead of repeating the same animation-state cleanup in multiple branches.
- Moved several repeated `getBuffer(...)` lookups out of render loops, including the legacy cube-particle path and the cube/ghost render passes.

Result:

- lower allocation pressure during combat rendering;
- less branch duplication in a large visual module;
- cleaner, more predictable render-state lifecycle.

### 12. RenderUtil API Cleanup

- Refactored the overloaded `Image` and `Gif` helper methods in `RenderUtil` to use shared internal draw helpers instead of repeating full builder chains in every overload.
- Removed unused imports from the utility file while preserving the existing public API used across the client.

Result:

- lower maintenance cost for UI/render helpers;
- smaller surface for copy-paste drift between overloads;
- cleaner utility code without behavioral changes.

### 13. NewGuiRender UI Frame Cleanup

- Cached static GUI texture identifiers for category icons, the back arrow, and color-picker assets instead of rebuilding identifiers from strings during render.
- Centralized per-frame clock sampling so search cursor blinking, string cursor blinking, and module shake animation all reuse the same timestamp-derived values.

Result:

- less avoidable per-frame resource churn in the clickgui;
- cleaner render signatures for panel/search/text-setting drawing;
- lower maintenance overhead in a large UI hotspot.

### 14. Target HUD Fade-Out Stability

- Preserved a `displayTarget` while the active target fades out so the HUD can keep rendering a stable entity until alpha reaches zero.
- Cached the preview target face texture identifier and synchronized remember/clear flows with the new display-target state.

Result:

- fixed a real null-state edge case during target fade-out;
- kept health interpolation tied to a stable render entity;
- improved predictability of the HUD render lifecycle.

### 15. Item Shader Profiles Screen Lookup Cleanup

- Added an item-id lookup table for the item catalog so preview/selection resolution no longer performs repeated linear scans over the full item list.
- Cached the selectable shader preset array inside the screen and routed theme-visibility refresh through a shared helper.

Result:

- lower UI overhead in the item shader editor;
- cleaner selection/preview control flow;
- less repeated allocation and snapshot boilerplate.

### 16. Alt Manager Filtered Selection Stability

- Made the filtered account list the source of truth for visible selection, keyboard navigation, and delete/restore actions, preventing hidden search results from remaining actionable.
- Limited mouse-wheel handling to the list region and removed repeated `indexOf(...)` work from the render loop.

Result:

- safer account operations while a search filter is active;
- cleaner UX when the visible list no longer matches the backing collection order;
- cheaper per-frame rendering in the alt manager.

### 17. WaterMark Layout Hardening

- Added explicit guards for zero-sized scaled/window dimensions before HUD layout, drag math, and editor rendering.
- Replaced direct mouse-coordinate scaling with a validated helper that returns a safe non-finite sentinel instead of dividing by zero during minimize/resize transitions.
- Pruned stale `segProgress` entries once their animation fully collapses so the watermark state map only retains active or animating segments.

Result:

- removed a real resize/minimize edge case that could produce invalid drag/layout coordinates;
- made HUD editor interactions resilient when the window briefly reports invalid dimensions;
- tightened the runtime footprint of the watermark segment animation state.

### 18. DashCubes Spawn Cache Hardening

- Re-keyed the placeable-spot cache by entity UUID instead of transient entity id values so despawn/respawn cycles cannot accidentally reuse another entity's cached placement state.
- Replaced repeated per-candidate `world.getOtherEntities(...)` collision queries inside the placement scan with a single nearby-entity bounding-box snapshot reused for the full scan.

Result:

- fixed a real cache-identity correctness risk in crowded sessions;
- removed a major source of avoidable world-query overhead from a tight spawn loop;
- kept the existing visual behavior while making the hotspot materially cheaper and safer.

### 19. Potion HUD Render Cache Cleanup

- Added a reusable per-tick effect render cache so sorting, name/time formatting, and width measurement are not rebuilt every frame.
- Reused a shared effect-sorting buffer instead of allocating a new effect list on each render pass.
- Cached mob-effect texture identifiers by path rather than rebuilding `Identifier` objects in the HUD path.
- Escalated texture fallback logging from silent debug-only behavior to bounded warn-once diagnostics.

Result:

- lower per-frame allocation pressure in the potion HUD;
- cleaner list/column rendering with less repeated formatting work;
- easier detection of degraded icon rendering without spamming logs.

### 20. Diagnostic Dedupe Bounding

- Replaced the unbounded one-shot diagnostic key sets in `HudRenderDiagnostics` and `KeyBindPolicy` with bounded FIFO dedupe storage.

Result:

- prevents slow memory growth in long client sessions;
- preserves once-only logging behavior without letting diagnostic caches grow forever.

## Overall Assessment

`New3` is in meaningfully better shape than a typical “latest working snapshot”:

- the mod builds;
- core hot-path code is already in a better state than older branches;
- storage logic is now more consistent and resilient;
- compiler noise is reduced;
- project structure is easier to understand and maintain.

## Remaining Risk Areas

- Several classes are still large and worth future decomposition even after the hardening pass:
  - `WaterMark`
  - `DashCubes`
- `src1/` can still confuse maintenance even though it is not part of the active build.

## Recommended Next Step

1. Run in-game regression coverage for HUD edit mode, potion HUD icon rendering, and DashCubes around dense entity groups.
2. Split `WaterMark` and `DashCubes` into smaller render/state services if another refactor pass is planned.
3. Keep further performance work driven by measured profiling, targeted caching, and culling rather than blanket feature reduction.
